# 课表规划 · Timetable Planner

> 第九届传智杯全国大学生数智创新与 AI 应用大赛 · AI 创新应用挑战赛（Vibe Coding）· C 组

**拍下你的课表，用说话的方式把学习安排进剩下的小时里，到点它叫你。**

通用的 AI 对话产品能给你一段"建议"，但它不知道你周三下午有课，也不会把那句话变成日程表上真正的一个色块。
本项目的取舍是：**确定性的事交给程序，生成性的事交给模型，最终决定权交给人。**

## 快速开始（约 10 分钟）

### 1. 环境要求

| 项 | 版本 |
|---|---|
| Node.js | ≥ 20（开发使用 24.x） |
| npm | ≥ 10 |
| 操作系统 | Windows / macOS / Linux 均可 |

### 2. 获取代码并安装依赖

```bash
git clone https://github.com/kinyicm/timetable-plan.git
cd timetable-plan
npm install
```

> 仓库内含 `.npmrc` 指向国内镜像，安装速度较快。若在海外，删除 `.npmrc` 即可切回官方源；依赖版本由 `package-lock.json` 锁定，与源无关。
>
> 注意：镜像源不实现 npm 的安全审计接口，直接执行 `npm audit` 会报 `NOT_IMPLEMENTED`。需要审计时临时指定官方源：`npm audit --registry=https://registry.npmjs.org`。

### 3. 配置模型 Key

```bash
# macOS / Linux
cp .env.example .env.local

# Windows
copy .env.example .env.local
```

用记事本打开 `.env.local`，填入你自己的智谱 API Key：

```
ZHIPU_API_KEY=你的Key
```

Key 可在 <https://bigmodel.cn/> 注册后免费领取（新用户有免费额度）。

> **Key 只从服务端环境变量读取，不会下发到浏览器。** `.env.local` 已在 `.gitignore` 中，不会被提交。

### 4. 启动

```bash
npm run dev
```

浏览器打开 <http://localhost:3000>。

生产模式（首屏更快，录屏演示用这个）：

```bash
npm run build
npm start
```

### 5. 首次使用的三步

1. **导入课表** —— 点「拍照上传课表」，选一张课表图片（或拍照），等 10–20 秒识别，在校对表格里改掉识别错的行，点「确认导入」
2. **说一句话安排任务** —— 在底部输入框打「每周三晚上 7 点到 9 点复习高数」，发送；网格上会真的出现这个事件
3. **查看冲突** —— 如果排进了上课时间，该事件会出现红色边框

## 功能说明

### 周视图

- 时间窗 `06:00`–`24:00`，每格 1 小时，共 18 行；横向 7 天。（早起与熬夜时段都在视野内，凌晨 0–6 点默认不显示以免挤压日间时段。）
- 纵向滚动限制在网格内部，页面本身不滚动；时间轴在横向滚动时固定。
- 事件按 `startMin` / `endMin` 绝对定位，高度与持续时长成正比。
- 颜色区分类型：课程（蓝）/ 任务（绿）/ 其他事件（灰）。
- 由识别而来、尚未经用户确认的事件右上角带 `?` 标记。

### 课表导入与校对

- 入口：`📷 拍照上传课表`（`<input type="file" accept="image/*" capture="environment">`）
- 上传前在**客户端**用 canvas 压缩：长边超过 1600px 等比缩小，JPEG 质量 0.82。
  - 原因：手机照片 4–6 MB，转 base64 后再涨约 33%，会超过服务端 8 MB 上限。开发日志中曾实际出现 `413`。
- 识别结果进入**校对表格**，每一行都可以改课程名/星期/起止节/地点，也可以整行删除。
- **不直接乐观写入**：识别一定会有误差，所以强制经过人工确认这一步。
- 未识别出课程名的条目会被丢弃，并以 `droppedCount` 形式告知用户。

### AI 落事件

- 输入框一轮对话 → 服务端 `/api/plan` → 模型返回**严格 JSON**：

```json
{
  "actions": [
    { "op": "add", "event": { "date": "2026-11-11", "startMin": 1140, "endMin": 1260, "title": "复习高数", "kind": "task" } }
  ],
  "reply": "已安排在周三 19:00-21:00"
}
```

- **程序侧二次校验**（不合法的直接丢弃并计数，不会污染日程表）：
  - 日期必须在本周范围内
  - `startMin` / `endMin` 必须在 `0..1440`
  - `endMin` 必须晚于 `startMin`
  - 标题不能为空
- 执行后新事件闪烁高亮 2 秒。

### 冲突检测

- 纯函数 `findConflicts(events)`：同一天、时间区间有交集即视为冲突。
- 一方是课程时提示「与上课时间重叠」，双方都是任务/事件时提示「两个安排时间重叠」。
- 在网格上用红色左边框标出。

## 设计原则

### 1. 确定性的事交给程序

| 谁做 | 做什么 |
|---|---|
| **程序** | 星期与节次的取值范围、`endMin > startMin`、同天区间是否相交、作息换算、图片压缩 |
| **模型** | 把课表图片读成结构化数据、把一句话理解成日程意图 |

理由：时间冲突是两个区间是否相交，**有明确对错**，必须由代码判定；
而"这句话指的是本周三还是下周三"这种歧义，才是模型该处理的部分。

### 2. 识别结果必须可校对

课表识别一定会出错（实测中合并单元格的节次跨度会被数错）。
因此导入结果**不直接写入日程**，而是进入可编辑的校对表格，由人确认后才生效。

### 3. 浏览器是不可信客户端

- 模型 Key 只存在服务端环境变量，**永不下发**。
- 五个接口都带滑动窗口限流（按客户端 IP，60 秒窗口）：`/api/plan` 与 `/api/recognize` **10 次/分钟**（高频操作），`/api/goal`、`/api/advise`、`/api/syllabus` **5 次/分钟**（低频重操作）。
- 模型密钥只从服务端环境变量读取，永远不会下发到浏览器；错误出口统一脱敏。
- 请求体积上限：图片 base64 8 MB、文本 500 字。
- 所有返回给浏览器的错误文本统一脱敏：若含 Key，替换为 `***`。

## 已知局限

如实记录，不隐藏：

1. **提醒需要软件保持打开。** 浏览器没有系统级后台定时权限，页面关闭后不会响铃。真正的系统闹钟需要桌面端常驻进程或手机原生 App。
2. **识别准确率依赖图片清晰度。** 合并单元格的节次跨度、模糊的课程名容易出错，所以强制校对。
3. **数据只存在本机浏览器。** 清除浏览器数据会丢失；换设备不同步（无账号体系）。
4. **课表只支持单周。** 不做单双周、不做调课周。
5. **限流是尽力而为。** 计数器在进程内存中，本地与单实例有效；多实例部署时各算各的，冷启动会重置。严格的全局限流需要外部存储。
6. **开发依赖中存在 7 个 moderate 告警。** 均在 `@typescript-eslint → minimatch`（lint 工具链），生产依赖为 0；升级需破坏现有 lint 配置，记录不修。
